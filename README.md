# HungerGames — Paper 26.2 / Folia 26.2

**Автор:** Dok_Si  
**Версия:** 1.6.4  
**Minecraft:** 26.2  
**Поддержка:** Paper 26.2 + Folia 26.2  
**Java:** 25

## Что это за плагин
HungerGames — серверный игровой режим в стиле «Голодных игр»: администратор создаёт арены, расставляет точки появления игроков и контейнеры с лутом, открывает сбор, запускает матч, после чего игроки сражаются до последнего выжившего. Состояние матча, выбытия, места и убийства сохраняются в истории.

## Доступ команд
Обычному игроку доступны только две команды:
- `/hg join` — автоматически войти на первую подходящую арену со свободным местом;
- `/hg join <арена>` — войти в сбор конкретной арены;
- `/hg leave` — выйти из списка участников или покинуть текущий матч.
Русские административные подкоманды обычному игроку недоступны. Все остальные команды HungerGames доступны только Dok_Si, OP и игрокам из `access.yml`.

## Арены и точки
Граничные точки задаются **киркой границ арены**. Если точка уже существует, её изменение или удаление не применяется по одному случайному клику: сначала появляется запрос подтверждения, затем второй такой же клик в течение 5 секунд выполняет действие.

Для каждой арены отдельно хранятся мир, две граничные точки, лобби и список точек появления. Граничные точки задаются **киркой границ арены**: ЛКМ — точка 1, ПКМ — точка 2. Если точка уже существует, её изменение или удаление требует двойного подтверждения: первый клик запрашивает подтверждение, второй такой же клик в течение 5 секунд применяет действие. В GUI ЛКМ по кнопке точки устанавливает её в текущей позиции сотрудника, ПКМ удаляет.

Точки появления являются отдельными «свободными местами» для участников. На них можно:
- добавить точку маркером точки появления;
- удалить точку ПКМ рядом с ней;
- удалить точку по номеру через GUI или `/hg спавн убрать <номер>`.

Во время сбора игрок получает первую свободную точку и телепортируется на неё. Пока участник находится в списке до начала игры, он не может покинуть свою точку: движение, телепортация и урон блокируются. После истечения настраиваемого обратного отсчёта начинается матч. Максимум участников можно выбрать для каждой арены: **вручную** (`max-players`) или **по количеству точек появления**. Во втором режиме 8 точек = максимум 8 игроков. Когда лимит достигнут, дальнейшее присоединение запрещается.

Все координаты сохраняются в `arenas.yml` отдельно для каждой арены.

## Сотрудники
Раздел **Сотрудники** показывает OP и выданный доступ, но **Dok_Si намеренно не отображается**. Любой сотрудник с доступом может добавлять и удалять выданный доступ. OP нельзя удалить через HungerGames, а Dok_Si является постоянным создателем и защищён от удаления.

## Наблюдение
Сотрудник может войти в текущий матч как:
- **SPECTATOR** — плагин временно включает SPECTATOR; после выхода возвращает прежний режим и исходную позицию;
- **Обычное наблюдение** — плагин не переключает режим игры и не очищает инвентарь. Такой сотрудник может продолжать пользоваться серверными системами, включая vanish/другие плагины.

Оба режима наблюдения имеют BossBar матча и не становятся участниками. Наблюдатель не может выйти за внешнюю границу арены. После окончания игры наблюдатель возвращается туда, откуда начал наблюдение; инвентарь обычного наблюдателя не трогается.

## Игроки и инвентари
Перед стартом матча для каждого участника сохраняются инвентарь, броня, off-hand, опыт, эффекты и исходное место. Игровой инвентарь очищается. При выбытии, `/hg выйти`, смерти или завершении матча исходное состояние возвращается. Вышедший с сервера во время матча считается выбывшим, а его сохранённое состояние восстанавливается при следующем входе.

## BossBar
BossBar матча показывается участникам (в том числе во время обратного отсчёта) и сотрудникам-наблюдателям этой арены. Она явно показывает текущую фазу: подготовка, старт через N секунд, защита, время до сужения, стадию сужения, время до следующей стадии, текущий тип границы и количество живых игроков. Обычные игроки сервера её не видят.

## Статистика
Во время каждого матча записываются UUID, ник, место, количество убийств, причина выбытия, убийца и время. В GUI есть:
- пьедестал 1/2/3 места;
- история выбивших игроков;
- отдельный **Топ убийств**, где каждый игрок отображается отдельной головой со своим скином, ником и числом убийств в lore.

## Сундуки и лут
Есть шаблоны лута, просмотр и редактирование их содержимого через GUI, маркеры типов контейнеров, шансы/количество предметов, заполнение при старте и периодическое повторное заполнение. В главном меню есть отдельный каталог специальных предметов: кирка границ арены, маркер точек появления и единый предмет «Макеты лута», который открывает список всех шаблонов с пагинацией. Из списка можно открыть шаблон или удалить ненужный шаблон.

### Как настраивается шаблон лута
1. `Главное меню → Сундуки → Создать тип` — сотрудник вводит имя типа, например `Редкий`.
2. Открывается карточка шаблона. Кнопка `Редактировать содержимое` открывает инвентарь из 45 ячеек: предметы, положенные туда, становятся источником лута. При закрытии/сохранении содержимое записывается в `chests.yml`.
3. `Мин. предметов` и `Макс. предметов` задают, сколько попыток выдачи предметов будет сделано при генерации сундука. Например, 2–5 означает случайное число от 2 до 5 попыток.
4. `Шанс предмета` задаёт вероятность успешной выдачи каждой попытки. При 70% часть попыток может не выдать предмет.
5. Количество конкретного предмета берётся из сохранённого стака в шаблоне: плагин случайно выбирает количество от 1 до количества, которое было положено в шаблон, с учётом максимального размера стака Minecraft.
6. Кнопка `Получить маркер` выдаёт уникальный предмет шаблона. С этим маркером сотрудник нажимает ПКМ по контейнеру на выбранной арене — контейнер получает тип шаблона.
7. При старте матча или при наступлении таймера обновления плагин очищает назначенный контейнер и генерирует новый случайный лут по его шаблону.

## Файлы
- `config.yml` — общие настройки и маркеры;
- `messages.yml` — все сообщения;
- `arenas.yml` — арены, координаты, точки появления, участники и настройки;

## Сборка
Проект использует Gradle и Paper API 26.2. Для сборки нужна Java 25. Версия 1.6.4 подготовлена для совместной работы с Paper 26.2 и Folia 26.2:

```text
./gradlew build
```

Для Windows:

```text
.\gradlew.bat build
```

JAR создаётся в `build/libs/HungerGames-1.6.4.jar`.




## Поддержка Paper и Folia

Версия 1.6.4 поддерживает **Paper 26.2** и **Folia 26.2**. В `plugin.yml` включён `folia-supported: true`. Код не использует старый `BukkitScheduler` для игровых задач. Вместо него применяются: **GlobalRegionScheduler** для глобального цикла матчей и BossBar, **EntityScheduler** для действий над игроками, и **RegionScheduler** для операций с блоками и контейнерами по месту их расположения. Эти scheduler API также работают на Paper.

Для Folia особенно важно не выполнять действия над игроком через `RegionScheduler`: EntityScheduler следует за игроком даже при его телепортации между регионами. Аналогично операции с блоками контейнеров выполняются через RegionScheduler региона, которому принадлежит нужная координата.

### Требования

- Paper 26.2 или Folia 26.2
- Java 25
- Один и тот же JAR `HungerGames-1.6.4.jar` используется на обеих платформах

## Контейнеры и шаблоны лута

Система лута не ограничивается сундуками. Поддерживаются блоки с Bukkit-инвентарём: сундуки, сундуки-ловушки, бочки, раздатчики, выбрасыватели, воронки, шалкер-боксы и другие блочные контейнеры, которые предоставляют `InventoryHolder`. Маркер типа лута из GUI работает ПКМ по такому контейнеру. Существующие записи в `chests.yml` остаются совместимыми.


### Поддерживаемые блоки для размещения лута

Через один и тот же маркер можно назначать шаблон лута на: сундук, сундук-ловушку, бочку, раздатчик, выбрасыватель, воронку, шалкер-бокс и другие блочные инвентари Paper, если их `BlockState` предоставляет `InventoryHolder`.

## Исправление лимита игроков

Если для арены включён режим **«Максимум игроков: по точкам появления»**, фактический максимум равен количеству точек появления.
При этом минимальное число участников автоматически не может превышать доступную вместимость арены. Например, при 2 точках и сохранённом минимуме 7 для запуска достаточно 2 участников.

## Повторный запуск арены

После завершения матча участники, их временные привязки к точкам появления и сессионные данные очищаются. Поэтому ту же арену можно снова запустить с теми же точками появления. При изменении списка точек старые привязки также сбрасываются.
